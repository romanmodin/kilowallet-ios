# Kilowallet iPhone 1.0: service privacy notes (RC3 integration)
Source: operator answers supplied November 2, 2026. Scope: TestFlight and App Store preparation. This is not a submitted Apple privacy label.

- Bridge (bridge.kilombino.com, Kilombino): the operator supports an onion route, but this RC3 iPhone source sets Bridge.torPort to null. It uses HTTPS through Cloudflare, which sees the connecting IP. The bridge keeps IPs in memory for rate limiting until one hour of inactivity; no IP is logged to disk. Onion requests expose no client IP to the bridge. Quote hash, amount and expiry persist until expiry plus one minute; proof retrieval token lasts one hour; re-quote guard lasts about eleven minutes per hash. The node retains a swap journal indefinitely: payment hash, destination invoice (including recipient node ID), amounts, preimage and state. Operator monitoring retains hashes and states; alerts include amount and truncated hash. No account or payer node ID is received. This does not imply the destination invoice is anonymous.
- Watchtower (Kilombino): onion only. Per-session public key distinct from node identity, encrypted justice blobs and 16-byte breach hints. Decryption requires the matching broadcast breach transaction. No invoices or payment hashes. Session data retained until client deletes session after its channels close. Ordinary rotated info-level LND logs.
- Default Ark server (ark.paperclippool.xyz): Paperclip Holdings LLC, a separate operator. According to the supplied description of its notice, it may retain IP logs, public keys, VTXO IDs, invoices, payment hashes, amounts and recovery data. Retention varies; signing and recovery journals may be long-lived. Notice: https://pool.paperclippool.xyz/privacy ; terms: https://pool.paperclippool.xyz/terms ; contact: contact@paperclippool.xyz. Verify published notice before public submission.
- Kilojoin over Tor: upstream RC3 (0ec864d669dc64ab4353c1be57e2deb3b418b7d3) adds RelayRoute. When Tor runs, try the onion relay first, then the public wss relay through Tor; both failures are an error, not a direct fallback. With Tor off, use a direct connection. Distinct connection isolation keys are passed through both Tor routes. This describes inspected source; actual simulator evidence and a physical-phone test must be recorded separately. RC3 still implements v1–v5 foreground rounds, not v6.
